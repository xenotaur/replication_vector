# EV-0009: Controllable Parent-Probe Tuning Sandbox

## Summary
- Added an opt-in browser sandbox at `?scene=sandbox` for keyboard-controlled parent-probe motion tuning.
- The sandbox sends keyboard thrust/turn input and developer-facing weight, inertia, and responsiveness sliders into Rust, then renders the returned parent-probe pose through Velumin `WebGPU.renderFrame(frame)`.
- The first-scene and deterministic replay render paths remain available.

## Evidence
- `replication_vector/src/simulation.rs` defines `ParentProbeTuningSliders`, `parent_probe_motion_config_from_tuning(...)`, and `step_parent_probe_motion_with_tuning(...)`.
- Slider midpoint values map to the existing `ParentProbeMotionConfig::default()` values.
- `replication_vector/src/lib.rs` exposes a Rust/WASM stepping boundary through `replication_vector_step_parent_probe_json(...)` and a sandbox frame path through `replication_vector_parent_probe_sandbox_frame(...)`.
- `replication_vector/web/index.html` enables the sandbox only for `?scene=sandbox`, captures `W`/`ArrowUp` thrust plus `A`/`ArrowLeft` and `D`/`ArrowRight` turn input, and keeps `first-scene` and `replay` routes intact.
- `replication_vector/web/render-smoke.mjs` now supports `SMOKE_SCENE=sandbox`, adjusts sliders, drives keyboard thrust/turn input, waits for the Rust-stepped state to move and turn, and saves PNG/JSON artifacts.
- `scripts/render-sandbox-smoke` builds the browser baseline and captures the sandbox route.
