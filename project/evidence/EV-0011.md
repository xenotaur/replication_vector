# EV-0011: Browser Mining Interaction and Resource Feedback

## Summary
- Added a `?scene=mining` browser route over the existing Rust-owned matter boundary.
- Added keyboard mining input with `Space`, while preserving parent-probe thrust and turn input.
- Added a Velumin-rendered resource source and conditional mining beam.
- Added inspectable Rust boundary metadata for active, inactive, out-of-range, and depleted-source behavior.

## Evidence
- `replication_vector/src/simulation.rs` reports active and in-range state from `step_mining(...)` without duplicating the range or transfer decision in JavaScript.
- `replication_vector/src/lib.rs` advances the existing Rust parent-probe motion model, invokes `step_mining(...)`, bounds delayed browser frames to the shared `0.05s` maximum, exposes the mining WASM boundary, and emits Velumin vector commands for the parent probe, source, and beam.
- `replication_vector/web/index.html` enables the mining route, sends keyboard state to Rust, renders the returned mining frame through `WebGPU.renderFrame(frame)`, and preserves the first-scene, replay, and tuning-sandbox routes.
- `replication_vector/web/render-smoke.mjs` captures the mining route and records five inspectable cases: initial inactive, active in-range, inactive, active out-of-range, and depleted source.
- `scripts/render-mining-smoke` is the opt-in browser/WebGPU smoke command.

## Browser/WebGPU Verification
- `scripts/render-mining-smoke` passed with a WebGPU-capable Chromium.
- Captured artifacts:
  - `replication_vector/web/smoke-out/mining.png`
  - `replication_vector/web/smoke-out/mining-active.png`
  - `replication_vector/web/smoke-out/mining.json`
- The active capture visibly contains the cyan parent probe, amber resource source, and green mining beam rendered through Velumin.
- Mining JSON cases proved:
  - active in-range: `beamActive: true`, positive matter extraction;
  - inactive: zero extraction;
  - active out-of-range: `inRange: false`, zero extraction, no beam;
  - depleted source: `depleted: true`, zero extraction, no beam.
- Existing `scripts/render-smoke`, `scripts/render-replay-smoke`, and `scripts/render-sandbox-smoke` also passed after the mining changes.

## Validation
- `scripts/version tools` passed: Rust `1.87.0`, wasm-pack `0.13.1`, Node `v20.20.0`, npm `10.8.2`, Vite `6.4.2`, Velumin `d3f67cf`.
- `scripts/format --check --diff` passed after rustfmt normalization.
- `scripts/lint` passed.
- `scripts/test --log` passed with 28 Rust tests and 0 failures, including a large-delta mining step bounded to `0.05s`.
- `scripts/baseline` passed.

## Result
- Proven: browser keyboard input can drive Rust-owned mining state and Velumin-rendered feedback without duplicating transfer, depletion, or range rules in JavaScript.
- Proven: existing static, replay, and parent-probe tuning paths remain available.
- Deferred: collision, docking, damage, shields, enemies, child probes, launch, scoring, progression, game-over, economy systems, alternate renderers, and broad visual-regression infrastructure.
