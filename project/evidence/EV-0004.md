# EV-0004: First Replication Vector Scene Expressed as Velumin Commands

## Summary
- Added the first Replication Vector-owned vector scene in `replication_vector/src/lib.rs`.
- The scene is expressed through Velumin-facing `VectorCommand` data.
- The scene includes a parent probe outline, asteroid outline, shield arc, and simple projectile line.
- Focused Rust tests validate the required primitive shapes without adding gameplay, physics, enemies, mining, progression, scoring, or an alternate renderer.

## Evidence
- `first_replication_vector_scene()` returns four Velumin commands:
  - a closed parent-probe `Polyline`;
  - a closed asteroid `Polyline`;
  - an open shield-arc `Polyline`;
  - a projectile `Line`.
- `replication_vector_scene_command_count()` exposes the project-owned scene count to the WASM/Vite harness.
- `replication_vector/web/index.html` now reports the rendering-spike scene command count instead of the older bootstrap triangle count.
- `scripts/test` passed locally with two focused tests:
  - `first_scene_uses_velumin_vector_commands_for_required_primitives`;
  - `outlines_are_closed_and_shield_arc_stays_open`.

## Velumin API Finding
- Replication Vector can construct project-owned Velumin `VectorCommand` scene data.
- The current Velumin browser API does not expose a public method that accepts downstream `VectorCommand` scene data for rendering.
- Observed boundary: Velumin's wasm-exposed `WebGPU.render()` renders an internal `smoke_scene()`, and `WebGPU.render_blasterites_tester()` renders another internal Velumin scene.
- Replication Vector did not add an alternate renderer or work around this API gap.

## Result
- Proven: project-owned scene data can be represented at the Velumin command boundary and validated by Rust tests.
- Not yet proven: direct browser rendering of downstream-owned scene data through Velumin.
- Next action: add or request an upstream Velumin API that lets downstream consumers submit `VectorCommand` scenes to the browser renderer.
