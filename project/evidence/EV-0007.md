# EV-0007: Deterministic Parent-Probe Motion Model

## Summary
- Added a Rust-only parent-probe motion model for the first core simulation slice.
- The model is independent from browser input, rendering, mining, shields, enemies, child-probe construction, scoring, progression, and Velumin.
- Focused Rust tests validate thrust, turn, drift, drag, speed caps, heading normalization, and deterministic fixed-step updates.

## Evidence
- `replication_vector/src/simulation.rs` defines:
  - `SimVec2`
  - `ParentProbeState`
  - `ParentProbeMotionInput`
  - `ParentProbeMotionConfig`
  - `step_parent_probe_motion(...)`
  - `normalize_heading(...)`
- `replication_vector/src/lib.rs` exposes the simulation module.
- Negative thrust is clamped to zero for this first slice, so there is no reverse thrust until future tuning work explicitly changes that behavior.
- The simulation step accepts explicit `delta_seconds` and does not read wall-clock time, random state, browser APIs, WebGPU state, Velumin renderer state, or global mutable state.

## Validation
- `scripts/version tools` passed.
- `scripts/format --check --diff` passed.
- `scripts/lint` passed.
- `scripts/test` passed with 10 Rust tests:
  - 8 simulation tests.
  - 2 existing render-scene primitive tests.
- `lrh validate` passed with 0 errors and 0 warnings.

## Result
- Proven: Replication Vector now has a deterministic, testable parent-probe movement and rotation model.
- Remaining risk: this model is not yet connected to browser input, rendering, mining range, collision, shields, or enemy pressure, all of which remain outside `WI-SIM-0001`.
